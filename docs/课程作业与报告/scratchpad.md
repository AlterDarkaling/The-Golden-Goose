# 背景和动机
本项目的“财务报告”页面此前功能复杂，易受数据结构差异与函数模板调用影响，导致金额不显示/NaN。现已用极简稳定版本恢复数字展示。目标是在保持稳定显示的前提下，分阶段逐步恢复丰富功能，并坚持：不在 WXML 中调用函数、全部在 JS 侧预计算可直接渲染的字符串。

# 关键挑战与分析
- 兼容历史/多来源数据结构（字段可能为 currentValue/originalValue/initialValue等，可能为字符串或对象）
- 避免 WXML 函数调用导致的渲染异常与性能问题
- 折旧、比率、趋势等计算需要健壮的数值处理与兜底
- 保持 UI 一致性，逐步恢复，同时避免一次性引入复杂度导致回归

# 高层级任务分解（按确认顺序）
1. 恢复利润表（基础版）
   - 预计算：工作/投资/经营收入、运营/财务/折旧费用、总收入、总费用、净收入
   - 输出：全部为字符串，写入 data.textIncome 与 data.incomeBreakdown
   - 成功标准：切换到“利润表”Tab时，所有金额均稳定显示，无 NaN/空白

2. 恢复资产/负债分项的占比文本
   - 预计算每类占比（%），写入 data.breakdown 中的 percentageText
   - 成功标准：资产、负债各分项显示“金额+占比”文本

3. 恢复现金流（基础版）
   - 预计算：经营/投资/筹资/净现金流，写入 data.textCashflow 与 data.cashflowBreakdown
   - 成功标准：“现金流量表”数字正确显示

4. 恢复折旧分析（简版）
   - 仅对消费性实物资产，基于原值、购买日期、折旧率（百分比/小数均可）作简化计算
   - 预计算结果为文本，写入 data.depreciationTextList
   - 成功标准：可见折旧条目清单，数字无 NaN

5. 恢复财务比率
   - 计算：流动比率、资产负债率、资产收益率、资产周转率、收入稳定性（文本百分比）
   - 成功标准：比率区卡片显示格式化文本

6. 恢复趋势图（CSS 柱状）
   - 生成净资产/现金流趋势的数列，映射为高度与文本
   - 成功标准：简单柱形图正常显示，数值文本正确

7. 恢复导出报告与智能分析
   - 使用已预计算文本拼装导出内容；“智能分析”仅基于已恢复的关键指标输出建议
   - 成功标准：导出弹窗文本完整、分析内容与指标一致

# 成功标准（统一）
- 页面所有金额/百分比均以字符串渲染，无 NaN/undefined/[object Object]
- WXML 不直接调用函数；所有展示字段均来自 data 中的预计算文本
- 切换 Tab/周期不出现 JS 报错

# 风险与回滚
- 风险：数据字段差异导致取值失败
  - 策略：使用 firstNumber(...) 与严格 Number.isFinite 校验
- 风险：逐步恢复导致 UI 不一致
  - 策略：每步只引入小范围 UI，保持现有样式
- 回滚：保留当前极简实现为基线，若失败，回退到当前版本

# 经验教训
- WXML 中调用函数易导致渲染异常与 NaN，统一在 JS 预计算成字符串更稳
- 对任何数值在显示前做 Number.isFinite 校验与兜底

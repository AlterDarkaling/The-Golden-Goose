## 一、项目定位

**论文题目**：基于微信小程序的多用户资产负债核算服务平台设计与实现

**一句话定性**：以《小狗钱钱》"鹅与金蛋"为隐喻，把企业会计准则（资产负债表 + 三大报表 + 折旧摊销）降维到个人理财场景的微信小程序。原生小程序前端 + Node.js/Express/Sequelize/MySQL 后端，JWT 鉴权，多用户数据按 user_id 隔离。

**与普通记账 App 的本质区别**：
- 普通记账记**收支流水**；本系统记**资产负债表**（净资产）。
- 把"工作"建模为产生现金流的资产（work_income），反算实际时薪。
- 消费型资产按折旧计量（手机/电脑每天吃掉多少钱）。
- 资产与贷款可关联，自动产出资产负债表、利润表、现金流量表。

## 二、系统架构与真实数据流

```
小程序页面（9页）
    ↓
SmartStorage（apiClient.js，ENABLE_CLOUD=true 硬编码）
    ↓
wx.request → http://localhost:3000/api
    ↓
Express：helmet → cors → 限流 → auth(JWT) → 路由 → 控制器
    ↓
Sequelize ORM → MySQL（users / assets / liabilities / saving_goals）
```

**关键事实**：
- 本地 StorageManager 仅用于用户信息、教程判断、备份恢复，**业务数据全部走云端**。
- 云端失败无本地回退：后端不启动 = App 不可用。
- 开发环境 auth 中间件对无 token 请求自动兜底 `dev_test_user`，真实多用户隔离需关闭此兜底并接入真实登录。

## 三、核心领域模型

**资产 5 大类**：
| 大类 | 子类举例 | 计量规则 |
|---|---|---|
| 流动资产 | 现金、短期理财 | 实际金额 / 应计利息 |
| 金融资产 | 股票基金、固定收益 | 市值重估，浮动盈亏 |
| 实物资产 | 消费型（手机/车）、增值型（房/黄金） | 余额递减折旧 / 市场估值 |
| 工作收入 | 本职、兼职 | 月薪结构反算实际时薪 |
| 其他资产 | 无形资产、预付资产 | 按有效期摊销 |

**负债 3 大类**：流动负债（信用卡/短借）、长期负债（房贷/车贷，等额本息/本金，含还款计划表）、其他负债。

**梦想储蓄罐**：12 类目标，按截止日倒推每日/每月应存。

## 四、硬伤清单（按重要性）

### P0 致命
1. **自动折旧对新数据失效**：`backend/utils/depreciation.js` 判断 `category_l1 === 'consumer_asset'`，新数据是 `physical_assets/consumer_assets`，消费资产价值创建后冻结。
2. **负债余额不随时间推进**：`getLiabilities` 直接返回 `current_amount`，不根据已过月数重算剩余本金，`paid_off` 状态不自动流转。
3. **前后端数据双轨断裂**：login 页写本地示例数据，首页从云端读，首次进入显示"暂无数据"但教程弹窗触发。
4. **BASE_URL 硬编码 localhost**：真机不可用，仅开发者工具 + 本机后端可演示。
5. **微信登录是空壳**：`WECHAT_APPID=test_appid`，jscode2session 必失败。

### P1 严重
6. **四套分类命名并存**：storage 默认、accountingCategories、login 示例、后端折旧判断互不一致。
7. **储蓄目标无自动完成逻辑**。
8. **密钥明文**：`.env` 含真实数据库密码、ENCRYPTION_KEY、dev JWT secret，`ALLOWED_ORIGINS=*`。
9. **字段转换靠手写 fieldMap**，易漏配。
10. **资产-贷款关联未接线**：模型 hasOne 关系存在，业务代码未回写 liability_id。

### P2 技术债
11. 死代码约 70KB：`financialStorage.js`、`newFinancialStorage.js`、`accountingEngine.js`、前端 `loanCalculator.js`。
12. 巨型单文件：`profile.js` 71KB、`edit.js` 55KB。
13. uni-app 残留：`pages.json`、`manifest.json`、`uni.scss`、`miniapp/` 空目录树。

## 六、多用户演示方案

**结论：本地后端 + 微信开发者工具演示，不上线体验版。**

理由：
- 体验版要求 HTTPS + 已备案域名（周期 2-4 周，来不及）。
- test_appid 下微信登录必失败，体验版会穿帮。
- dev 兜底 `dev_test_user` 会把多个用户合并成一个人，反而暴露问题。

**演示前必做**：
1. 关闭 auth 中间件的 dev 兜底。
2. 加 `POST /api/auth/dev-login` 接口，传昵称/模拟 openid，签发 JWT。
3. 前端 login 页加身份切换入口（张三/李四两个测试身份）。

**演示流程**：
1. 开发者工具登录"张三"，录资产"手机 8000 元"。
2. 清缓存，登录"李四"，录资产"相机 5000 元"。
3. 切回张三，只见手机；Navicat 展示 assets 表两条记录 user_id 不同。
4. Apifox 展示同一接口带不同 token 返回不同数据。

**手机号授权**：个人主体小程序拿不到 `getPhoneNumber`，不要演示此功能，改用头像昵称填写能力。

断裂 ① 数据双轨
首次进入，示例数据写入本地 storage；首页却从云端加载（此时为空）→ 列表显示「暂无数据」，而本地数据又触发教程弹窗。
断裂 ② 真机不可达
BASE_URL 写死 localhost:3000，手机无法访问开发机回环地址 → 仅能在开发者工具 + 本机后端下演示，无真机可用性。
断裂 ③ 登录是空壳
.env 为 test_appid，微信 jscode2session 必然失败；实际靠 login 页本地造用户 + dev 后端兜底 dev_test_user，微信登录链路从未真正跑通。
② 核心领域模型 — 企业会计科目表的个人化改造
资产 5 大类 / 负债 3 大类 / 梦想储蓄罐；括号内为该科目的计量规则
资产 Assets
流动资产：现金类、短期理财（实际金额 / 应计利息）
金融资产：股票基金、固定收益（市值重估，数量×现价，浮动盈亏）
实物资产：消费型（手机/电脑/车/家电）、增值型（房产/黄金/收藏）（余额递减折旧 / 市场估值）
工作收入：本职、兼职（按月薪结构反算实际时薪，含薪资历史）
其他资产：无形资产、预付资产（按有效期/服务期摊销）
负债 Liabilities
流动负债：信用卡、短期借款（花呗/亲友/现金贷）
长期负债：房贷、车贷/消费贷（等额本息/等额本金，存还款计划表）
其他负债：应付款项、预收款项
梦想储蓄罐 SavingGoal
12 类（应急/购房/教育/旅行/投资/养老/购车/婚礼/健康/还债/礼物/其他）；按目标额与截止日倒推每日/每月应存，状态 active/completed/cancelled。
科目命名实际存在 4 代并存：① storage 默认的 investment/digital 体系 → ② accountingCategories 的 current_assets 体系（表单在用）→ ③ login 示例数据的 fixed_assets / long_term_debt 体系（与科目表对不上，显示为「未知」）→ ④ 后端折旧兼容的 consumer_asset（单数旧名）。
